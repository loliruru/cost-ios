# Phase 6 统计与异常

「统计」提供近 7、30、90 天和最长 3,660 天的自定义区间。收入、支出和净额按冻结本位币分别显示。同币种的冻结金额以涉及区间的最高精度对齐，保留历史小数位。日趋势含零账单日，可按月、季、年查看。平均支出按覆盖的自然周期计算，首尾未满期标明。环比使用紧邻的等长区间，同比将起止日分别回拨一年，2 月 29 日在平年落到 2 月 28 日。零基准仍显示绝对变化。

沿用 v1 表和索引。SQLite 通过 `cost_minor_sum` 对冻结 minor units 做整数分组并返回十进制文本，整数中间和接近上限时转入任意精度累加。分类构成使用叶分类金额。Swift Charts 折线展示最近最多 120 个所选粒度的区间，趋势明细可读取全部周期和精确收支。构成图单独显示前七项，其余扇区合并，分类列表逐项显示准确金额、占比与环比。

0.6.1 / build 8 的「异常开支」使用最近 7 或 30 天的候选，以及候选开始前 30 天或 90 天的基线。仅检测活动非周期支出，分别评估单笔、单日总额和单日叶分类。阈值由中位数、MAD、IQR、活跃中位数和均值计算。第 2,001 行触发样本超限提示。结果按日期排序，最多显示最近 30 项和总数。开关和灵敏度保存在本地设置，忽略本次或相似金额 ±20% 的正常反馈保存在账本的反馈表，可经确认清除。

## V1 实施前复核

V1 已获准实现方案 B 的金额异常、覆盖确认与描述性频率统计、今日累计及跨午夜刷新。分类使用独立基线。频率屏幕以中性色展示覆盖日、支出日、比例和不足原因。CMH、门槛和状态机仅作为研究记录。本节的构建、测试和 IPA 状态以文末的验收记录为准。

### 完整业务日与覆盖期

设当前业务日为 `D`，窗口为 `W`。频率候选的起止日为 `[D−W,D)`，使用截至昨天的完整业务日。30 天历史区间为 `[D−W−30,D−W)`，必要时换用 `[D−W−90,D−W)`。用固定评估日期 2026-11-23 的模拟时钟举例，近 7 天为 11-16 至 11-22，近 30 天为 10-24 至 11-22。实际运行以设备当前业务日计算，11-22 在其当地午夜结束后才有资格纳入频率统计。金额候选用 `[D−W+1,D+1)`，今天的单日结果标为「今日累计 · 临时」。账单用冻结业务日分组，前台跨本地午夜或业务时区变化时重算。

覆盖期由用户确认。开始日期默认明日，用户可以选择较早且已完整记账的日期。打开 App、导入旧账或保存一笔补录均不会确认覆盖。暂停当天排除，恢复从次日开始。暂停、未知或只覆盖部分时段的日期排除在计数之外。用户可补录账单，也可独立追认完整历史日期。补录到一个已覆盖日可能把该日从无支出改成有支出，补录到未知日的账单可进入金额基线，频率等覆盖确认后再纳入。按账本在本地保存已确认区间、暂停和明确未知的空档。

### 金额公式与精确比较

金额阈值为 `max(m+kS,rm)`，其中 `S=max(1.4826×MAD,IQR/1.349)`，全部基于正额历史样本。低、标准、高灵敏度的 `(k,r)` 分别为 `(6,3)`、`(4,2.5)`、`(3,2)`。设历史正额样本可表示的最小单位为 `q`，则 `m≥q` 且 `r≥2`，所以 `m+q≤2m≤rm`。V1 直接使用两项阈值。单笔和单日分类按自身分类独立计算，不从父分类或兄弟分类借用。5–9 个样本标记「样本较少」，10 个及以上只改变展示分档。空数组、全零和少于五个正额样本返回样本不足。

把同本位币的金额按冻结 scale 归一到整数单位。中位数与 MAD、IQR 系数以及比例项按精确整数或有理数计算。比较 `候选整数×分母 > 阈值分子`，对每个阈值分支都成立才触发。展示时可舍入金额，判定用精确值。例如阈值为 `40 + 120000/1349 ≈ 128.9547813` 元，冻结两位精度的 128.95 元不触发，128.96 元触发。恰等于 100 元时不触发，100.01 元触发。历史 `1、1、1、1、5` 元的标准阈值为 2.50 元，2.51 元及 5 元可触发。

### 研究记录 · R 官方 CMH 精确条件基准

按星期几分层。每层用时期（候选、历史）作为行，有无合格支出作为列。对固定的各层行列边际，在原假设下卷积层内超几何权重。单侧 `greater` 取候选中有支出日数总和大于等于观测值的尾部。原假设为各星期层的共同优势比 `θ=1`，方向性备择为同一 `θ>1`。星期几校正了每周构成差异，而共同优势比用于解释各层中方向一致的时期效应。 [R stats 文档](https://stat.ethz.ch/R-manual/R-patched/library/stats/html/mantelhaen.test.html) · [R 官方实现](https://svn.r-project.org/R/trunk/src/library/stats/R/mantelhaen.test.R)

少数星期层若边际固定，仅贡献常量。所有层都固定时，研究检验没有可比较的变异。历史覆盖不足或候选星期在历史中缺少可比天数时，V1 显示覆盖不足。已知阶段性批量补记、强相邻依赖或有明确证据显示不同星期的变化方向相反时，合并优势比和显著性不宜用于告警。稀疏或完全分离时优势比点估计可以趋近零或无穷，研究回放只用精确尾部概率和实际增幅作为触发条件。单窗口精确 p 值的前提是层内可交换性，滚动窗口和相邻日依赖分别带来重复检验和模型失配。

### 研究记录 · 频率告警状态机与 90 天回放

前台只评估当前选中的币种和 7/30 天窗口。币种独立保存状态，同一币种的两个窗口共用状态。每个币种每个业务日只用首次可评估的选择推进状态，刷新、同日切换窗口和重开 App 不重复推进。历史至少 28 个已覆盖完整日，候选中出现的每个星期几在历史至少覆盖 3 次。候选 7/30 天分别至少覆盖 5/21 个完整日。历史满足条件时优先 30 天，否则扩展到 90 天。

频率增幅 = 候选有支出日比例 − 按候选星期构成加权的历史有支出日比例。研究模拟对照了增幅至少 25 个百分点时的 `p ≤ 0.05` 和 `p ≤ 0.0005`。若每次检验的 p 值有效且窗口预先确定，固定币种 90 次检验在后一阈值的并集上界为 4.5%。切换币种或窗口、数据依赖选择和相邻日强相关时，回放计数用于评估风险。V1 运行时频率只计算近期与历史的描述性指标。

假设上次在业务日 `A` 用 `W₀` 发出提示。当次记录锁住同币种，重复满足条件时复用既有提示。重新触发需同时满足以下条件。

1. `D≥A+W₀`，上一次窗口长度的冷却已结束。
2. `D−W≥A`，新候选期起点已到达上次候选期的右边界，两个候选期互不重叠。
3. 上次触发后，有连续 3 个实际评估的业务日使用同一窗口长度，且每次频率增幅均低于 10 个百分点。恢复可用任一窗口。中途切换窗口、缺评、覆盖不足或未达恢复门槛均打断这三天。已满足覆盖要求但各星期层的支出状态都固定时，按可观测增幅 0 计入恢复，页面显示没有可检验的对比。恢复达标后重新进入可触发状态，仍需通过前两个条件和新的告警门槛。

回放为每个场景 1,000 条独立账本序列。预热 120 天，再从星期一开始连续评估 90 天，全部业务日标为已覆盖。随机数用 xorshift32，按左移 13、无符号右移 17、左移 5 的顺序异或。独立场景种子 `0x6a09e667`，持续聚集场景种子 `0xbb67ae85`，每个场景连续取样。每条序列按 CNY、JPY 顺序生成，工作日/周末的重新取样概率分别为 CNY 20%/45%、JPY 35%/60%。重新取样时，均匀随机数低于当日概率即计一个支出日。聚集场景从第二天起先抽取是否沿用前一天的值，65% 概率沿用，其余时候重新取样。沿用形成相邻日相关，星期转换时的实际边际概率还取决于前一天的状态分布。切换场景每 7 天轮转 CNY 7、CNY 30、JPY 7、JPY 30。整个回放使用固定生成规则，没有注入频率上升。

| 无变化场景 | 选中范围 | 每场景评估数 | p≤0.05 原始触发 / 实发误报 / 拦下重复 | p≤0.0005 原始触发 / 实发误报 / 拦下重复 | p≤0.0005 至少一次误报的序列 |
|---|---|---:|---:|---:|---:|
| 按星期独立 | CNY 7 天 | 90,000 | 1839 / 723 / 1116 | 7 / 3 / 4 | 3 / 1000 |
| 按星期独立 | CNY 30 天 | 90,000 | 1091 / 257 / 834 | 9 / 5 / 4 | 5 / 1000 |
| 按星期独立 | 币种和窗口切换 | 90,000 | 1636 / 658 / 978 | 0 / 0 / 0 | 0 / 1000 |
| 持续聚集 | CNY 7 天 | 90,000 | 10650 / 1951 / 8699 | 1234 / 485 / 749 | 446 / 1000 |
| 持续聚集 | CNY 30 天 | 90,000 | 10038 / 907 / 9131 | 2245 / 321 / 1924 | 313 / 1000 |
| 持续聚集 | 币种和窗口切换 | 90,000 | 11254 / 2317 / 8937 | 1755 / 563 / 1192 | 468 / 1000 |

「拦下重复」含告警尚未恢复、冷却或候选重叠而拦下的触发日，每行等于原始触发减去实发。「实发误报」是告警事件次数，包含同一序列恢复后再次误报。末列按序列去重。持续聚集的 7 天模式是 **485 次误报、446 条序列至少一次误报**。固定 30 天是 **321 次、313 条**，切换币种和窗口是 **563 次、468 条**。各有 39、8、17 次为恢复后再次误报。同一告警事件内实发重复数为 0。用 0.0005 门槛对照两次真实高频段（日期序号 `[10,24)`、`[64,82)`），7 天模式于第 15、69 日发出两次研究提示，拦下 14 个重复触发日。30 天模式于第 21、81 日发出两次，拦下 28 个重复触发日。连续高频对照在两种窗口各只发一次。

收紧门槛和冷却改善了按星期独立的回放结果。持续聚集时，至少出现一次误报的序列仍占 31.3%–46.8%。这是模型适用性风险，和同一事件的去重效果分别报告。覆盖确认只能说明日期可纳入计数，层内可交换性是另一个前提。

频率告警重新启用前，研究将比较 Markov 与连续消费区间等正常消费模型，加入星期、工资日、节假日和消费聚集程度，采用保留时间相关性的 Block Bootstrap 或等效校准。应在独立的 90 天测试集中报告每 1,000 条序列至少一次误报的条数，同时报告真实频率上升的检出率和检测延迟。建议至少一次误报的序列比例控制在 5% 以内，再考虑启用告警。校准必须处理时间相关性。
