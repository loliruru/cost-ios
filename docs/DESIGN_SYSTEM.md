# Cost iOS 设计系统

状态：原生导航和业务表单已在 Phase 3 交付。Phase 9 的材质、布局与真机验收见 [Phase 9](PHASE9_NATIVE_APPEARANCE.md)。

## 信息层级

原生 SwiftUI、NavigationStack、TabView、系统 Sheet/菜单、SF Symbols。顶级目的地为账单、模板、循环、统计、设置；分类/账户/标签、资金、备份为次级入口。iOS 重新设计交互与布局，不照搬 Material 组件、AGSL、Android 玻璃透镜实现或其像素值。

1. 内容层：账单、数字、图表和正文，稳定低噪声。
2. 结构层：系统分组 surface、输入区域、间距及边界建立层级。
3. 控制层：导航、浮动操作、Sheet 标题和临时筛选可使用 Glass；长表单内容仍优先清晰。

避免 Glass inside Glass、逐账单 blur、全屏折射、持续装饰动效。Android 已获 PASS 的材质不等于 iOS 视觉已通过。

## 平台材质与封装

导航、Tab、快速录入 Sheet 和记账按钮的材质选择集中在 `CostChrome`。正文沿用系统分组背景、列表与表单。标准排版、触觉和动效分别由 DesignSystem 中的组件处理。

iOS 26 以系统材质呈现导航、Tab 与 Sheet，记账按钮使用受可用性保护的 `glassEffect`。iOS 18 使用 `ultraThinMaterial` 回退。开启降低透明度或增强对比度时使用不透明系统背景。低电量模式将记账按钮改用系统材质。

材质切换保留原有控件尺寸、顺序与语义。系统负责页面转场和 Sheet 动画，降低动态效果时关闭应用自定义的账单变更动画和录入展开动画。关键记账操作成功后提供触觉反馈。

## 排版、颜色和布局

使用系统文本样式与 Dynamic Type，金额可用 monospacedDigit，币种 code/symbol 消歧，关键数位不截断。数字格式化消费精确值或字符串，不转 Double；布局和动画的浮点坐标不属于金额计算。

Light/Dark 分别使用语义色，不简单反相；收支、选中、异常同时以文本/符号表达。普通文字对比以至少 4.5:1 为目标；透明背景需局部保护，透明效果不能优先于阅读。

控件至少 44×44 pt 有效触控范围，允许大字体增高、换行、滚动。适配 iPhone 尺寸、安全区、横竖屏和键盘，保存/关闭始终可达。快速记账主屏优先金额与分类，次要输入按需展开。输入采用系统控件，中文组合/光标/选区不被异步回传重置。

## 动作与无障碍

动画表达空间和因果，可打断；容器变化不能拉伸正文。Reduce Motion 使用短淡入或即时切换，结果相同；重要保存/错误以明确文字反馈，触觉仅补充，遵循系统设置。

VoiceOver 提供名称、角色、选中/停用状态、金额币种与完整操作。装饰 emoji/图片/SF Symbol 不创建重复焦点，图表提供区间、总额、趋势和数据点文字替代。Sheet 模态期间隔离下层焦点；关闭后恢复合理焦点，取消交互保留草稿、不保存交易。

## 用户视觉资源

内置图标、emoji、受管图片为互斥图标来源，背景独立，保留语义 fallback。输入上限沿 Android 契约：16 MiB、单边 16384 px、40 MP；图标最长边 512 px、背景最多 1920×1080、派生图最多 8 MiB。静态派生图去原始元数据、按 hash/处理版本去重、稳定引用，停用不清资源，零引用才回收。

Android 备份图片为 WebP。Phase 3 已实测系统仅能解码，用户随后明确批准最小 libwebp 编码依赖（见[ADR-011](DECISIONS.md)）；受管副本仍为真实 WebP。完整备份双向交换在 Phase 8 验证。原图、外部 URI、设备绝对路径、用户个人目录不进入 schema 或备份。

## 验收边界

Phase 3 随功能验证原生控件、深浅色、键盘、Dynamic Type、VoiceOver 和交互；Phase 9 集中精修 Glass、图标、动效与整体材质。自定义新材质先做有界假数据样例再铺开，不在先前功能阶段批量投入自定义光学效果。

自动检查客观布局、语义、对比和任务可达性；美感/材质/动效观感由用户真机审美验收。届时提供操作、预期及 PASS/FAIL 反馈方式。Phase 0 无需视觉验收，也不生成图标或截图。
